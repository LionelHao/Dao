# Design Brief: T-0039 真人邀请与 Agent 配置入口

## 依据

- 产品 PRD 2.3 #6：真人通过邀请加入并可接受或拒绝；Agent 通过配置参与度和工具权限立即加入。
- 产品 PRD 2.3 #13：真人成员关系与 Agent 成员关系必须使用不同数据和界面语义。
- 桌面端设计稿 S6：同一房间入口中并列呈现「邀请真人」和「配置 Agent」，不得合并成通用成员表单。

## 设计哲学

克制的功能主义协作台。视觉差异必须直接服务语义：等待真人回应使用蓝色虚线和 pending 文案；立即生效的 Agent 配置使用实线角色面板、参与度和工具授权。颜色不承担真人与 Agent 的全部区分，结构、控件和措辞必须共同表达差异。

## 成功标准

- 桌面宽度并列展示两条加入路径；窄屏重排为单列且没有横向滚动。
- 真人表单只产生 `HumanInvitationRequest`，明确说明等待接受或拒绝。
- Agent 表单只产生 `AgentConfigurationRequest`，必须同时选择参与度和至少一项已声明工具权限。
- 控件不小于 44px，使用原生 label、fieldset、legend、状态区和可见焦点。
- 明暗模式均使用共享 token；正文达到 WCAG AA，控件边界达到 3:1 非文本对比度。
- 无效、空权限和篡改输入不会触发回调，并与具体控件建立持续可访问的错误关联。

## 范围边界

本视图只验证两条入口的界面、类型和回调载荷。网络请求、远端部署、完整登录和移动端产品形态不属于本任务；375px 只用于验证桌面视图在窄窗口下能安全重排。
