# T-0037 人 / agent 的视觉分离渲染 · 工作笔记

## 验收标准（逐条抄录）

1. 头像形状按设计稿 T-01：人为圆形、agent 为圆角方形。渲染组件在类型层面由 `actor.kind` 决定形状，不接受手工传形状参数。
2. 人的消息为气泡样式、agent 的消息为左侧角色色轨，两者版式可在截图上一眼分辨。
3. 存在一个自动化测试：给定同一段文本，分别以 human 与 agent 身份渲染，断言两者的 DOM 结构或 class 不同。
4. 角色色盘至少 5 色且与语义色（成功/警示/危险）无重叠；超过 5 个 agent 时的降级策略已实现（图案或首字冗余编码）。

## 原语与边界

- 覆盖 PRD 2.3 #1「在场」在渲染层的物理区分：人表示可达性，agent 表示就绪度；本任务不把两者合并为同一个状态视觉。
- 数据层：`HumanActor` 与 `AgentActor` 已由 T-0036 以不同字段（`reachability` / `readiness`、`toolPermissions`）定义；`Actor` 为不可互赋的联合类型。
- 接口层：T-0011 的发送服务校验消息 `authorKind` 与 actor kind 一致，渲染不接受独立的形状覆写参数。
- 渲染层：本任务让圆形气泡与圆角方形角色色轨成为可截图和 DOM 断言的不同视觉原语。

## 设计与参照

- 设计稿 T-01、C-01：人用圆头像 + 气泡；agent 用圆角方头像 + 角色色轨。
- 参照 Buzz 的客户端可独立增加视图、服务端为规范源的边界；翻译为 Electron/TypeScript 的纯渲染器只消费已校验的 `Actor` / `Message`。
- 偏离：Buzz 虽将 agent 作为一等参与者，但没有拆开人 / agent 的原语视觉。本产品按 DEC-010 和 PRD 律一显式分离，不复制其共享参与者视觉抽象。

## 实施顺序

1. 先为相同文本的身份差异、六个 agent 的降级冗余写失败测试。
2. 用最小实现提供五槽非语义角色色与第六位起的图案 / 首字冗余编码。
3. 让桌面渲染器在显式视觉预览入口展示同屏对照，保留默认空群聊。
4. 在构建产物上截图审查桌面、平板、手机断点，并运行干净克隆五项门禁。
