# T-0014 编辑撤回与表情回应的人 / agent 分治 · 工作笔记

**目标：** 在服务 API 和页面上把人的可修订社交言论与 agent 的追加式行为记录严格区隔。

## 蓝图验收标准（原文）

1. 人的消息可编辑可撤回；agent 的消息在 API 层就拒绝编辑与撤回请求（返回明确错误，不是 UI 隐藏按钮）
2. agent 消息的更正走追加：原消息保留不变，更正内容以关联条目追加在后，两者在界面上都可见（设计稿 C-05）
3. 人对人的表情回应不触发任何系统行为；人对 agent 的 👍/👎 写入一条校准信号，可被发言判定逻辑读取
4. 存在测试：对 agent 消息发起编辑或撤回请求，断言返回错误码而非成功

## 参照、翻译与偏离

- **参照什么：** Buzz 持久事件追加、提交后副作用的不可回滚语义；PRD 2.3 #5/#11/#12、5.8、6.3 第四层和设计稿 C-05/C-06。
- **怎么翻译：** 人消息记录持有编辑/撤回状态；agent 更正创建 `AgentCorrection` 关联项，原消息不可变。人对 agent 的 👍/👎 追加 `CalibrationSignal`，人对人只追加社交回应。
- **为何偏离：** 不复制 Nostr 可替换事件或审计链；本地 primitives 用独立集合保留追加关系，并明确不将表情本身误当通用系统动作。

## 文件与测试先行顺序

1. 写 agent 编辑/撤回明确错误与人编辑/撤回成功的失败用例。
2. 写更正关联、原记录不变及两者均渲染的失败用例。
3. 写人对人零校准、人对 agent 👍/👎 可被判定查询读取的失败用例。
