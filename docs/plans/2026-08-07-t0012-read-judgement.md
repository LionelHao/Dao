# T-0012 已读 / 已判定分离 · 工作笔记

**目标：** 把人的社交已读与 agent 的发言判定分成不同结构和呈现，保证沉默可解释。

## 蓝图验收标准（原文）

1. 人显示已读回执（谁读了）；agent 不显示已读，改显示【已判定】三态之一：将回应 / 无需回应 / 被抑制
2. 每条「已判定」必须携带一句可读原因（如「未命中我的领域」「同话题冷却期内，还剩 N 分钟」），原因来自发言判定逻辑而非固定文案
3. 存在测试：agent 收到一条消息但不发言时，界面上必然出现一条「已判定」记录——不允许静默沉默
4. 已读与已判定在数据模型上是两个不同的结构，不共用同一张表或同一字段

## 参照、翻译与偏离

- **参照什么：** Buzz `StoredEvent` 的可重放事件理念与 `EventQueue` 的显式命运分类；PRD 2.3 #2、5.3、6.3 和设计稿 P-02。
- **怎么翻译：** `HumanReadReceipt` 与 `AgentJudgement` 是名称、字段和存储集合均分离的 TypeScript 结构；路由输入生成原因字符串，渲染只消费其记录。
- **为何偏离：** 不复制 Nostr event kind/tag 或 Buzz 的通用队列；V1 只公开三种判定命运及可读理由，不实现路由模型。

2. 写“无需回应仍生成记录”和动态冷却原因用例，再实现判定写入。
3. 写 DOM 测试：人的已读名单与 agent 的已判定理由不共用 class，随后实现预览。
