# T-0013 @ 的请求 / 调用双语义 · 工作笔记

**目标：** 让 `@` 按对象产生请求承诺或可中断执行，而不是只替换文字颜色。

## 蓝图验收标准（原文）

1. @ 人与 @ agent 在渲染上可辨：@ 人为虚线下划线样式、@ agent 为实心角色色块（设计稿 T-02）。有测试断言两者 class 不同
2. @ 人产生一条待答项（owner = 被 @ 者，状态：待回应 / 已回应 / 已搁置 / 已转交），可被查询；@ agent 直接触发执行，不产生待答项
3. @ agent 的执行可中断：执行中有明确的中断入口，点击后 agent 停止且状态回到 ready
4. agent 无法拒绝 @ 调用（无「拒绝」路径）；人可以搁置或转交，且转交链被记录
5. @all 只 @ 全体 agent 不 @ 人；@here 仅群主可用且有频率限制

## 参照、翻译与偏离

- **参照什么：** Buzz mention 事件到 `EventQueue`/`AgentPool` 的执行链，以及其显式取消、重排、失败命运；PRD 2.3 #4、5.4、7.12.2 和设计稿 T-02/P-04/C-03。
- **怎么翻译：** TypeScript `address` API 返回具判别标签的 `OpenItem` 或 `AgentExecution`；中断经真实工具调用的 `AbortSignal`，人请求的搁置/转交单独记录。
- **为何偏离：** 不复制 ACP pool、channel queue、dead-letter 或认证；本地单 room 以可观测的 mock 工具执行演示命令的必响应和取消，而非为 agent 增加“拒绝”状态。

## 文件与测试先行顺序

1. 先写人请求生成/查询待答项、agent 调用不生成待答项、转交链和无拒绝路径的服务失败测试。
2. 先写可中断慢工具的测试，再实现 `AbortController` 生命周期与 ready 回归。
3. 先写 `@all` 只选 agent、`@here` 群主与限频的测试。
4. 最后先写 DOM class 断言与中断按钮交互测试，再实现渲染。
