## 六条验收标准与证据

### 1. 闭合 BallInCourt 与唯一状态映射

- `packages/core/src/collaboration.ts` 定义 closed `BallInCourt`、`BlueprintBallFact` 和严格 guards；每个球只包含 holderId、roomId、source kind/id、reason、since、deadline。
- `projectBallsInCourt` 只读取权威字段：OpenItem awaiting/transferred 的 current owner；LightTask claimed 的 claimant；delivered 的已持久 verifierActorId；Blueprint task/awaiting 的单一 assignee 与 blocked fact 的单一 mentioned actor。todo/verified 不产球。
- `collaboration.test.ts` 与 `collaboration.type-test.ts` 覆盖文本、verifierRole、多人 holder 集合、额外字段和 ambiguous blocked mention 拒绝，不允许推测 holder。

### 2. 同一查询覆盖三类 room，转交与 replay 保持单一当前 holder

- `executeBallAuthorityOperation` 在一个 AuthorityWorker 查询中合并当前 OpenItem、LightTask 与 bounded Blueprint read port；`ball.query` 在同一固定 authority 读取中返回 `balls`、当前 principal 的 `needsAction` 与 `reminders`。
- source key 为 `sourceKind + sourceId`；同一 Blueprint source 的旧 replay 不覆盖较新 `since`。OpenItem 转交与 LightTask deliver 后只投影新 owner/verifier。
- `ball-authority.test.ts` 用真实 SQLite 覆盖 OpenItem transfer、LightTask deliver、Blueprint awaiting；`collaboration.test.ts` 覆盖 Blueprint assignee 更新后旧 replay 去重。

### 3. agent 结构触发不可抑制，human 不被代言

- 逾期 agent ball 在 AuthorityWorker transaction 内写唯一 `ball_boundary_claims`、`room.ball.overdue` event/outbox 与 closed `BallSummary`；human ball 只写 reminder boundary claim并返回 `NeedsActionProjection`/`ReminderCandidate`，不生成 agent event 或 human 消息。
- route authority 只消费仍与当前 source/holder/since 匹配的 agent claim，并在同一事务写 `route_consumed_at`；该 BallSummary 令恰好一个 RouteJob 的 `hasBall=true`。T-0016 的既有判定将 ball 作为不可被 soft suppression 压制的结构输入，实际回答、进展或 failed/blocked 继续走唯一 route/AgentRuntime 链路。
- `ball-authority.test.ts` 断言首次 route snapshot 为 `hasBall=1`、后续为 `0`，agent event 恰好一个、human reminder 恰好一个，且没有建立第二套路由或伪造 human 发言。

### 4. 确定性阈值、边界 exactly-once 与重启恢复

- OpenItem 与 LightTask deadline 由 server-private 配置注入；Blueprint task/awaiting 固定七天，明确 blocked mention 立即到期。生产默认 OpenItem/LightTask 为 24 小时。
- `ball_boundary_claims` 以 room/source/holder/since/deadline/boundary kind 唯一约束 claim；阈值前为空，边界时首次创建，重复扫描和 SQLite 重启不重复 event/reminder。
- `ball-authority.test.ts` 用 `t0+59,999ms`、`t0+60,000ms` 和真实 reopen 验证边界；`ball-runtime-service.test.ts` 验证 room recovery、有界 Blueprint read、跨 room fail-closed 与 clean close。

### 5. 当前权限、同步恢复与历史事实保留

- `ball.query` wire payload 不接受 actorId；WebSocket 从 authenticated session 得到 principal，AuthorityWorker 每次复核 active room 与当前 membership。
- removed member 不能再查询；agent claim 在 route consumption 前再次比对当前 membership 和 source 状态。权限收紧不删除 OpenItem/LightTask 历史承诺事实。
- `authority.e2e.test.ts` 以真实 compiled server、AuthorityWorker、SQLite 和两个 WebSocket 客户端验证同一 LightTask holder；正常停机、删除 snapshot cache、重启后 holder/needs-action 仍一致。`ball-authority.test.ts` 验证成员移除后的拒绝与历史行保留。

### 6. 仅 room-scoped needs-action/reminder，未读与行动分离

- Core 只交付 `NeedsActionProjection`、`ReminderCandidate` 和 `BallOverdueTrigger`；没有跨 room inbox、通知策略或送达通道。
- `renderRoomAttentionSummary` 把 `.room-attention-summary__unread` 与 `.room-attention-summary__needs-action` 分开；`app.test.ts` 断言 unread=0 时持球行动项仍可见。
- Blueprint 只提供 `BlueprintBallProjectionPort.readRoom(roomId, AbortSignal)` 和有界空 production adapter；真实 GBP 接入/写入留在 M5。跨 room adapter 输出 fail-closed，fake port 仅由 deep test seam 注入。

## 安全与一致性边界

- 事实源：Ball 是现有权威承诺事实的只读投影；v10 只持久化不可重复的逾期边界 claim，不建立第二个状态库或事件总线。
- holder：不读取消息正文、不展开角色、不接受多人集合；Blueprint port 返回非 closed、超过 256 条、跨 room 或超时都失败关闭。
- 权限：查询、逾期事件、outbox delivery 和 route consumption 都按当前 room/member/actor kind 复核。
- agent/human：agent 才能产生 `room.ball.overdue` 和 route BallSummary；human 仅有本人的 room-scoped needs-action/reminder，系统绝不代 human 发言。
- exactly-once boundary：SQLite unique claim 保证逻辑边界一次；outbox 仍保持既有 at-least-once transport，replica 用稳定 eventId 去重，二者不混称物理 exactly-once。
- 有界性：最多跟踪 256 rooms、每 room 最多 256 Blueprint facts；Blueprint read 默认 2 秒并受 AbortSignal 控制，扫描 coalesce，关闭会停止 timer 并 abort 在途读取。
- 范围：没有实现跨群五分区收件箱、通知送达、T-0020 人来让位或 M5 GBP 写入。
