# T-0013 @ 的请求 / 调用双语义 · 交付说明

## 1. 做了什么

建立人类 `@` 请求与 agent `@` 调用的不同 API、状态机与视觉：前者创建可转交待答项，后者立即启动可中断的真实 mock 工具调用。

## 2. 逐条对照验收标准

1. **满足** — 「@ 人与 @ agent 在渲染上可辨：@ 人为虚线下划线样式、@ agent 为实心角色色块（设计稿 T-02）。有测试断言两者 class 不同」：`.mention--human` 与 `.mention--agent` 分别使用虚线下划线和实心紫色块；`app.test.ts` 直接比较 class。
2. **满足** — 「@ 人产生一条待答项（owner = 被 @ 者，状态：待回应 / 已回应 / 已搁置 / 已转交），可被查询；@ agent 直接触发执行，不产生待答项」：`addressHuman` 返回/保留 `OpenItem`；`addressAgent` 返回 `AgentExecution`，测试确认调用后待答项仅有人的请求。
3. **满足** — 「@ agent 的执行可中断：执行中有明确的中断入口，点击后 agent 停止且状态回到 ready」：`addressAgent` 使用 `AbortController`，`interruptAgentExecution` 中断工具并令 `waitForAgentExecution` 得到 `interrupted` / `agentReadiness` 回到 `ready`；预览按钮也直接更新执行与可见状态，DOM 测试覆盖点击。
4. **满足** — 「agent 无法拒绝 @ 调用（无「拒绝」路径）；人可以搁置或转交，且转交链被记录」：没有 agent reject 状态，调用 `rejectAgentExecution` 返回 `agent_cannot_reject_invocation`；`transferOpenItem` 保存 `fromId`/`toId`/时间/原因，测试和预览都显示周安全 → 陈研发。
5. **满足** — 「@all 只 @ 全体 agent 不 @ 人；@here 仅群主可用且有频率限制」：`addressAll` 只遍历 agent；`addressHere` 要求 `roomOwners` 匹配并以时间戳限频，测试断言非 owner 与第二次请求被拒绝、仅 online human 是接收者。

## 3. Buzz 参照与偏离

- **参照了什么：** Buzz 的 mention 事件经过 `EventQueue`/`AgentPool` 调度、取消、重排与可见状态的执行链。
- **怎么翻译：** `AgentExecution` 保存调用源、状态、工具和结果；`AgentToolInvoker` 接收 `AbortSignal`，待答项则是独立的 `OpenItem`/转交链。
- **为何偏离：** 不复制 ACP worker pool、channel queue、dead-letter 或认证；关键偏离是强制实现 PRD 的请求/调用差异，Buzz 不提供这组人/agent 原语分治。

## 4. 解锁了什么

为 **T-0016 四层发言判定 · 单次路由架构** 提供可中断的执行端点与待答项承诺基础，也为 T-0017 待答项后续扩展留下查询接口。
