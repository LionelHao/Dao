# T-0036：项目骨架与零 I/O 领域内核

交付分支：[`feat/claude/t0036-foundation`](https://github.com/LionelHao/Dao/tree/feat/claude/t0036-foundation)  
审阅入口：[PR #1](https://github.com/LionelHao/Dao/pull/1)

## 1. 做了什么

建立 pnpm TypeScript workspace、`@native-im/core` 零 I/O 领域内核与 Electron 桌面端最小空群聊，并为类型、依赖边界和渲染建立本地及 PR CI 质量门。

## 2. 逐条对照验收标准

1. **满足**：从远端特性分支做全新浅克隆后，已实际运行 `pnpm install && pnpm typecheck && pnpm lint && pnpm test && pnpm build`，五条命令均零报错。
2. **满足**：`packages/core` 导出 `Event`、`Actor`、`Message`、`Room` 及相应运行时类型守卫；其 `package.json` 没有运行时依赖。`scripts/verify-core-boundary.mjs` 拒绝 I/O 依赖和导入，且由本地测试与 PR CI 执行。
3. **满足**：`HumanActor` 使用 `reachability: online | dnd | offline`，`AgentActor` 使用 `readiness: ready | busy | paused | noauth`；`actor.type-test.ts` 以编译期负例断言不可向 agent 赋予 `reachability`。
4. **满足**：Electron 主进程能启动实际窗口并加载空群聊；窗口与渲染测试覆盖标题和空态文案。DEC-012 已记录选择 Electron 的全 TypeScript、当前编制和最小运行时边界判据，及不选择 Tauri 的跨语言成本。
5. **满足**：`.github/workflows/quality.yml` 在 PR 上运行类型检查、lint、核心边界验证和测试；`main` 分支保护将 `typecheck, lint, and test` 设为必需状态检查，失败阻断合并。PR #1 的最新一次该检查已通过。
6. **满足**：本说明的下一节逐项说明了参照的 buzz 模块、翻译方式与偏离理由，满足 DEC-010。

## 3. 参照与偏离

- **`crates/buzz-core` → `packages/core`**：参照其“事件与领域类型集中、零 I/O、服务层不得反向依赖”的边界，将其翻译为 TypeScript 的领域联合类型和类型守卫，并以静态边界验证守住依赖方向。偏离：本阶段没有复制 Nostr kind、签名验证、租户上下文或 filter；这些属于尚未建立的服务端协议与授权边界，先写入会把未验证的传输语义固化进领域内核。
- **`crates/buzz-relay` 的 composition root → `packages/desktop/src/main.ts`**：参照运行时适配层只装配基础设施、领域模型不承担窗口 I/O 的原则。偏离：此处只提供 Electron 窗口适配器，不实现 relay、数据库或实时分发；T-0036 的范围是可启动骨架而非消息基础设施，提前引入后端会越过后续任务的验收边界。
- **buzz 的分层 CI 质量门 → `.github/workflows/quality.yml`**：参照将结构性边界纳入自动化门禁的做法，针对当前仓库设置 TypeScript 类型、lint、测试与零 I/O 断言，并作为 PR 合并必需检查。偏离：未照搬其跨平台、数据库集成和 Relay E2E 矩阵；当前尚无服务端、持久化或多端协议，这些检查没有可验证对象。

## 4. 解锁了什么

T-0036 完成后，依赖它的 **T-0011 消息基础设施与人 / agent 视觉分离** 具备可认领前提；其后续链路包括 T-0012、T-0013、T-0014、T-0037 与 T-0038。蓝图当前仍由上游展开和验收状态控制可认领池，故本交付不越权改变这些任务的状态。
