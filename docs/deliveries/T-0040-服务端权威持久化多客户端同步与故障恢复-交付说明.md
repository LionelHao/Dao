# T-0040 服务端权威持久化、多客户端同步与故障恢复交付说明

## 一、做了什么

把身份、群与九类协作事实收束到 worker-owned SQLite authority，以稳定事件/幂等键、事务 outbox、版本迁移、cursor/repair/streaming 协议和三真实 WebSocket replica 完成跨进程故障恢复；客户端缓存只作为可清除、可原子重建的副本。

Renderer 不是 raw JSON 断言：[`app.test.ts`](../../packages/desktop/src/renderer/app.test.ts) 将 typed restored records 实际交给 renderer fixture，再用 DOM class、custom fields 与可见文案「已读」「已判定」「待答项」「Agent 执行」「纯社交」「校准」分别证明三组语义不混淆。Streaming repair 在 `snapshot.completed` 前断言 live cache 仍为旧的完整版本；materialized C 在 test transport 已收到最后一页但尚未返回 replica 时暂停，证明 10,000 records 已收齐但 live count/checksum 仍为空，释放后才原子提交。

10,000 条压力数据由 compiled-child 的 closed fixture builder 生成：先逐条用 production core guard 验证 actor/membership/read/message/judgement/open/execution/calibration，开启 SQLite FK，再以单事务 bulk insert。精确分布为 1 room、2,000 memberships（2,000 个不同合法 actor）、3,500 messages、1,999 reads、500 judgments、500 open items、500 executions、1,000 calibrations。三连接同属一个 session family；A 用比生产上限更严格的 deep-only 50 records/page 完成 200 页 streaming fallback，B/C 在正常 quota 下各完成 100 页 materialized repair。`ClientSyncReplica` 自身只保留当前 page/envelope，canonical verification 由 cache staging port 增量承担；E2E memory cache 则刻意保存完整 catalog/10k `RoomRepairRecord` values，从 values 独立重算 checksum，并深比较三 cache。丢字段/改 body 的 mutation test 必须 checksum fail，不允许回显 authority checksum 伪通过。此证据只覆盖 mixed snapshot streaming fallback、分页与 replica 原子 swap；它不冒充 10,000 次 production command，也不用于证明相应 event/outbox 数量。

## 三、参照与偏离

| Buzz module / symbol | TypeScript 翻译 | 偏离与理由 |
| --- | --- | --- |
| `buzz-relay handlers/ingest` | closed command、AuthorityWorker、同事务 domain/event/idempotency/outbox | 不复制 Nostr 签名事件；服务端身份与 human/Agent 分治是本产品边界 |
| `buzz-relay handlers/req` | `SyncQueryStore`、`SyncService`、cursor/repair/page/complete | 不复制 Nostr filter/EOSE；closed v2 protocol 更贴合 room authority |
| Buzz `SubscriptionRegistry` | room/principal/session-family 反向索引 + 当前权限复核 | Redis/topic 不作授权边界；Alpha 保持单机，durability 由 outbox/cursor 提供 |
| `dispatch_persistent_event` | COMMIT 后 OutboxDispatcher | 明确修正 Buzz 提交后 best-effort spawn 的 crash window；允许 frame 重放，用 stable eventId 幂等 |
| workflow `ActionSink` | `CommandStore` / `SyncQueryStore` port | 只复用依赖倒置思想，不声称复用 Buzz persistence API |
| relay E2E / 持久事件 | compiled child + 三真实 WS + 三 replica | 不引入 Rust/Postgres/Redis/mesh，不做完整 Event Sourcing；SQLite 领域表是 Alpha 权威 |

完整 closed frames、errors、cursor ordering、权限、refresh、outbox、migration/import 与逐项 reference/translation/deviation 见 [`authoritative-sync.md`](../protocols/authoritative-sync.md)。
