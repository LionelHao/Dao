# T-0020 · 人来让位的硬规则 · 交付说明

## 一句话结果

已实现不可配置、权威可恢复的 human preemption fence：human 消息先持久接受，再取消同 room 的安全可取消旧 attempt，随后基于最新 room 状态路由并为实际选中的 Agent 创建带 lineage 的新 execution；旧结果、重复触发、进程重启和连续插话均不能越过该边界。

## 六条验收标准与证据

### 1. 复用 T-0041 生命周期和有界 scheduler

- `packages/core/src/collaboration.ts` 继续使用 `AgentExecution` 的 queued/running/completed/failed/cancelled 五态，只追加 closed `supersedesExecutionIds` lineage；没有新增第二套 execution 状态表、事件总线或 scheduler。
- replacement 是新的 queued execution/attempt，旧 execution 保持 cancelled；`agent_fence_replacements` 只记录不可改写的 old-attempt→replacement 关系。
- `packages/server/src/agent-runtime/agent-runtime-service.ts` 继续复用 room FIFO、每 room 32 queued、全进程 8 active 和闭合 429/`retryAfterMs=1000`。human fence 的进程内 post-commit 队列另有 256 pending、每批 256、最多 32 批的恢复上限，不承载 execution 调度。
- 证据：既有 scheduler FIFO/并行/429 tests 保持通过；`human-preemption-runtime.test.ts` 另覆盖 orchestration queue overflow 后依赖 durable recovery，不创建无界 Promise/数组。

### 2. 固定顺序与准确 eligibility matrix

- human `message.send` 的 AuthorityWorker transaction 只先写 durable message/event/idempotency/outbox；生产 `HumanPreemptionRuntime` 随后严格执行 `cancel-for-human-fence → apply committed cancellation/AbortSignal → create-route-after-human-fence → route notify`。
- cancellation transaction 只命中同 room、human accepted fence 之前的 queued、running/waiting_upstream、running/tool_call+not_started；running/model_generation 与 tool_call+dispatched 保持运行。规则没有配置开关，也不读取 Agent participation。
- claim/complete 事务还会检查 execution source event 之后是否已有 durable 但尚未处理的 human message；因此 message commit 与 cancel transaction 之间的 worker 排队窗口中，旧 queued 不能抢先变成 generating，waiting/tool-not-started 也不能抢先完成。已经在 generating 的 execution仍允许完成。
- RouteJob 只在 cancellation receipt 已提交后创建，沿用 T-0016 单次路由，并读取事务提交后的最新 membership、calibration 和 ball 状态；route terminal 后才允许 replacement。
- 证据：`human-preemption-authority.test.ts` 用真实 SQLite 覆盖五类 eligibility、route 前无 Job、取消后建 Job、selected/unselected Agent；`human-preemption-runtime.test.ts` 精确断言 commit/abort/route/notify 顺序。

### 3. 迟到结果隔离与可恢复 lineage

- cancellation 同时 CAS `agent_executions` 和当前 `agent_execution_attempts` 为 cancelled，持久化 `human_preempted:<sourceHumanMessageId>`、完成时间和 `agent_human_fences`；旧 attempt 的 complete 继续由现有 executionId+attemptSeq+status CAS 拒绝，不能写 Agent message 或 completed。
- replacement 不复活旧 execution；其 `supersedesExecutionIds`、`agent_fence_replacements`、routeJobId、selectedAgentId 和 oldAttemptSeq 均持久化。SnapshotWorker 的 materialized/streaming repair 都恢复该 closed lineage。
- 证据：真实 SQLite test 断言 late completion 失败且 message 行为零；真实 AuthorityWorker close/reopen 后 cancellation reason、attempt status 和唯一 fence receipt 仍可查询；Core guard 拒绝空、重复、自引用或越界 lineage。

### 4. 仅 human 新消息触发，且逻辑 exactly-once

- production composition 只在 authenticated human `message.send` durable ACK 后调用 preemption runtime；Agent message 只走既有 route notify，系统事件、history、sync/repair 不进入 fence 入口。
- `human_preemption_fences.source_human_message_id` 为唯一 receipt；`agent_human_fences` 以 fence+execution 唯一，`agent_fence_replacements` 以 fence+old execution 唯一。相同 human command replay 返回同 cancellation/route/replacement，不重复 event 或关系。
- 证据：Authority test 对 cancellation 和 replacement 都做 exact replay，并断言每条 human fence 只有一个 `room.human_preemption.applied`；连续第二条 human message只取消第一条 replacement 一次。既有 human/Agent message idempotency、history、sync 和 restart suites 全部保持通过。

### 5. 队列满、provider、crash/restart 与连续插话不留僵尸

- queued execution 在 committed cancellation 后从现有 room queue 移除；running eligible execution 的 AbortSignal 也只在 AuthorityWorker commit 后传播。provider partial 不能完成为 message，已被 fence 的 attempt 不会进入自动 retry。
- startup recovery 有界扫描已 durable accepted 但尚无 RouteJob 的 human message；零取消也持久化 receipt，保证不会因“当时无旧 execution”而反复触发。route/replacement 失败保留 durable human message与 terminal/cancelled old execution，后续恢复不会把旧 work 变回 queued/running。
- 证据：provider fake test 同时覆盖 active upstream abort、queued work removal、complete 调用为零；真实 AuthorityWorker 两次启动覆盖 pending scan、cancel replay、route 补建和无 zombie attempt；真实 SQLite test 覆盖连续插话；全量 compiled-child/WebSocket crash/restart、snapshot cache-clear 和 T-0041 provider timeout/retry suites均通过。

### 6. 独立客户端语义

- Core 新增 closed `room.human_preemption.applied` / `HumanPreemptionNotice`，与 message recall、Agent failure 和 execution lifecycle event 类型均不同；server persistence parser、outbox、delta/subscribe 同时闭合验证 room/occurredAt。
- desktop `renderHumanPreemptionNotice` 使用独立 `.human-preemption-notice`；旧 execution 使用 `.agent-invocation--human-preempted`，replacement 使用 `.agent-invocation--requeued` 与 `data-supersedes-execution-ids`。
- 证据：Core sync/parser tests 拒绝额外字段与错误 room；desktop DOM test 断言 notice 文案、cancelled/requeued class，并断言 execution 文案不含“撤回”或“调用失败”。既有 partial preview 仍是非权威且没有 typing animation。
- T-0020 增加的 durable room events 扩大了 repair→subscribe 接管窗口；`client-sync-replica.ts` 现在只忽略 cursor 已覆盖的同 room 握手旧批次，仍拒绝跨 room、游标前跳和非连续流。对应回归 test 在固定 Node 22.13.1 下覆盖 snapshot-covered unseen event，并以真实进程 E2E 重复验证多客户端 clear-cache/restore。

## 安全与一致性边界

- human-first：message accepted transaction 与 cancel/route transaction 分开，确保 durable message 永远先于取消、路由和 replacement 可见；ACK 不冒充 Agent execution 已完成。
- cancelability：model_generation 和 dispatched side effect 明确不取消；不把取消说成回滚，也不改变 T-0041 的 `outcome_unknown`/不可自动重放边界。
- stale fencing：old execution/attempt 永远 terminal cancelled；late provider/tool result 无法写 message、completed 或覆盖新 lineage。
- routing：不在旧上下文上重启模型；每条 human message仍只有一个 T-0016 RouteJob。未选中或当前已移除 Agent 不能得到 replacement。
- authorization：replacement 只能来自 route authority 已持久化的 will_respond intent，并在 AuthorityWorker transaction 内复核 active room/current Agent membership；没有 Agent 身份旁路。
- boundedness：candidate 上限 33（32 queued + 最多 1 个 room active）、recovery scan 256×32、runtime post-commit pending 256；真正执行继续受 room 32/global 8 约束。
- secret：T-0020 不新增 secret、provider正文、header、日志或诊断持久化；继续继承 T-0041 server-side SecretProvider 和 sentinel tests。

## 已知风险与 reviewer 建议

- human message 与 fence/route 是故意拆开的多个 AuthorityWorker transaction；进程在任一边界退出时靠 pending scan 补齐，因此 reviewer 应重点复核“message durable 但 route 尚未创建”的重启窗口和 bounded recovery。
- running/model_generation 允许完成，随后同 room replacement 才执行；这是批准的“已开始生成可说完”例外，不是可配置策略。建议 runtime reviewer 复核 room serial scheduler 与 AbortSignal eligibility。
- replacement 当前按 selected Agent 合并同一 fence 中该 Agent 的多个 old attempts，用一条新 execution 的 lineage 指向全部旧 attempt；建议 route/domain reviewer确认该 coalescing 与“一条消息对同一 Agent 只调用一次”的 T-0016 invariant一致。
- notice 是 durable delta/outbox event；full repair 通过 execution cancellationReason/supersedes lineage恢复当前状态，不把历史 notice 复制成第二份当前事实。建议 sync/desktop reviewer复核 delta与cache-clear后的两种呈现。
- 建议至少由一名 AuthorityWorker/SQLite reviewer、一名 route/runtime concurrency reviewer，以及一名 core/sync/desktop reviewer验收。
