# T-0018 · 轻任务：轻量群的最小承诺 · 交付说明

## 六条验收标准与证据

### 1. 完整 closed LightTask 与角色/时间审计

- `packages/core/src/collaboration.ts` 定义 `LightTask`、四态、criteria、verifier role 和只读 projection；`isLightTask` 严格拒绝未知字段，并闭合 todo/claimed/delivered/verified 的 actor、role、timestamp 与 criteria 关系。
- `packages/core/src/collaboration.test.ts` 覆盖四态、同 claimant/verifier、同 claimantRole/verifierRole、未完成 criteria 验收及 GBP 字段注入反例；`collaboration.type-test.ts` 锁定编译期不接收 deps。
- `packages/server/src/persistence/schema.ts` 的 immutable v9 `light_tasks` 用 CHECK/trigger 锁定同 room source、human audit actor、前向状态、冻结审计字段、criteria 稳定 ID/文本/顺序和 verified 全 met。

### 2. “我来做”只是意图，只有显式确认创建且 ACK 重试幂等

- `packages/server/src/protocol.ts` 只接受 closed `light-task.create`，不存在自然语言 intent→task 入口；create 的 `requestId` 是稳定 transport idempotency key，ACK retry 必须复用同一 frame/key。
- `sqlite-authoritative-store.test.ts` 先权威写入正文为“我来做”的普通消息并断言 `light_tasks=0`，再显式 create；相同 idempotency key 精确重放同一 ACK，改变 payload 返回 409 且不重复。
- `protocol.test.ts` 明确拒绝 `light-task.intent`。取消确认不发送 durable command，因此与 intent-only 路径相同为零任务写入。

### 3. 单向状态机、唯一异角色验收者与 criteria 门禁

- `authority-database-handler.ts` 在 claim 时原子冻结 claimant/current role；deliver 只允许当前 claimant，并把不同于冻结 claimant role 的 verifierRole 解析为恰好一个当前 human member；verify 只允许已持久化 verifierActorId。
- `sqlite-authoritative-store.test.ts` 覆盖不同角色唯一 actor 成功，以及同 actor、不同 actor 同 role、0/N（无唯一解）和已移除 claimant 拒绝；所有无唯一解状态返回 409，权限失效返回 403。
- 同一测试覆盖 verifier-only criterion tick、非空 criteria 未全部 met 的 409、空 criteria 缺少显式确认的 409，以及确认后 verified；terminal/跨级/重复转换由 CAS 与 schema trigger 双重拒绝。

### 4. AuthorityWorker 原子事务、多客户端、重启、清缓存与成员移除

- create/transition/criterion 都由 `executeHumanDatabaseCommand` 的 `BEGIN IMMEDIATE` transaction 执行；事实、`room.light_task.changed`、room outbox 和 idempotency acknowledgement 在同一事务提交。
- `snapshot-worker.ts` 同时在 materialized scan 与有界 keyset streaming 中导出 `kind: "light-task"`；`sync.ts`/`contracts.ts` 对 repair/event payload 做 closed guard。
- `authority.e2e.test.ts` 使用真实 compiled server、AuthorityWorker、SQLite 和两个 WebSocket 客户端证明显式 create/replay 后两客户端 repair 一致；正常停机、删除 snapshot cache、重启后仍恢复唯一任务和 criteria。
- `sqlite-authoritative-store.test.ts` 删除 claimant membership 后保留 claimed 历史行，但新 deliver 被当前权限复核拒绝。

### 5. 桌面四态且无 GBP 控件，API 同时闭合拒绝

- `packages/desktop/src/renderer/app.ts`/`styles.css` 显示 todo/claimed/delivered/verified、claimant、verifier role/actor、source 和 criteria；LightTask 视觉与 OpenItem、AgentExecution 分离。
- `app.test.ts` 覆盖四态、audit 信息、criteria met 和无 deps/maturity/milestone 控件。
- `protocol.test.ts` 与 `persistence/contracts.test.ts` 对 deps、maturity、milestone、Blueprint task ID、外部 status 注入逐项返回 closed invalid request；不是仅靠 UI 隐藏。

### 6. GBP-independent 只读 projection，不写 Blueprint

- `projectLightTask` 只导出 id、roomId、sourceMessageId、title、claimant、status、criteria，不需要 GBP runtime 或 task ID。
- room repair 的 LightTask record 保留上述来源与 checklist，真实重启/清缓存证据验证无损恢复。
- 本任务未实现 Blueprint adapter 写入、未伪造 GBP task ID，未修改任何 Blueprint HTML/JSON；升级写入继续留给 M5。

## 安全与一致性边界

- 身份：只有 authenticated human command 可创建/流转；claimant 与 verifier 由 server session/membership 决定，wire payload 不能指定 actor。
- 状态：应用层按动作检查 + SQLite CAS + immutable trigger，禁止回退、跨级、terminal 改写和审计 actor/role 重写。
- 角色：claim 冻结角色快照；deliver 每次基于当前 membership 唯一解析并持久化 verifierActorId，不在后续阶段重新猜角色。
- 成员变化：历史 actor/role 不级联删除；任何新写入继续复核 active room membership。
- 同步：partial/client-local intent 不进入事实；只有 committed LightTask event 进入 event/history repair/outbox，多客户端消费同一 streamSeq。
- 范围：没有加入 T-0019 BallInCourt、GBP task、依赖图、maturity、milestone、blocked/dropped/superseded。
