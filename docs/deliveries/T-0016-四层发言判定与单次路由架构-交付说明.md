## 二、七条验收标准与证据

### 1. 一条消息一个 RouteJob；单次摘要路由；显式 @ 不双启动

- `packages/server/src/persistence/authority-database-handler.ts` 的 message authority transaction 同时写 message、`message_topics`、唯一 `route_jobs`、attempt 1 和创建时的 `route_job_agents` 快照；`source_message_id UNIQUE` 与命令幂等共同阻止重复 Job。
- `packages/server/src/route-runtime/openai-router-provider.ts` 只发送闭合 `RouterProviderInput`：当前消息摘要、room phase、role / participation / capability、校准、持球和版本化 topic 参数；请求固定 `store:false`，不读取完整历史、工具参数或 credential。
- direct `@agentId` 在 route claim 中确定性解析，并在 `route_invocation_intents` 与 T-0041 `agent_invocation_intents` 的 `(sourceMessageId, targetAgentId)` 唯一边界去重；路由完成后只走 `runtime.invoke-routed`。
- 自动化：`sqlite-authoritative-store.test.ts` 的 “commits one route job…” 覆盖两名 Agent 仍只有一个 Job、ACK 幂等和一次执行；`route-runtime-service.test.ts` 覆盖 summary-only input 与 mandatory/provider 合并。

### 2. 闭合有序候选；mandatory 优先；恶意或失配 plan fail closed

- `packages/core/src/collaboration.ts` 定义并严格守卫 `RouterPlan`、`RouterCandidate`、`RouteInvocationIntent`；候选必须按 1..N 连续排序，不允许额外字段、重复 Agent、未知 trigger / reason。
- `packages/server/src/route-runtime/route-decision.ts` 先 direct、再 structured help / ball、最后 provider candidate；同一 Agent 只保留一个 intent，direct 优先。
- structured help 仅接受 Agent-authored source；human-origin 结构化候选与非成员、重复、越界候选闭合拒绝。route complete 与 `runtime.invoke-routed` 分别复核当前 room、成员与 Agent kind，形成两次独立权限检查。
- 自动化：`route-decision.test.ts` 覆盖 direct 优先、structured help 来源和三档参与度；`openai-router-provider.test.ts` 覆盖额外字段、重复候选、缺 secret 零 fetch；SQLite 测试覆盖成员在 claim 后被移除时 judgment=`permission_denied` 且无 execution。

### 3. silent / on-mention / active 严格分层

- `route-decision.ts` 允许 direct 唤醒所有三档；structured help 只允许 on-mention / active；领域、风险和持球主动触发只允许 active。
- silent 的 direct intent 是单消息、单 execution 的一次性事实，不修改 membership participation，因此回应后自然仍为 silent。
- T-0019 尚未提供权威球来源；本任务按批准边界交付闭合 `BallSummary` / `hasBall` 输入 seam 和不可抑制决策，生产投影保持空值，不从文本或模型猜球。
- 自动化：`route-decision.test.ts` 的 participation、Agent-only structured help、execution phase/ball 用例覆盖允许与拒绝矩阵。

### 4. 四条抑制及固定默认值

- `assignTopicKey` 仅读取最近 8 条可见摘要，固定 `dao-topic-embedding-v1`、64 维稳定 hash embedding 与 cosine `>= 0.82`，并将版本、N、阈值和 topicKey 持久化。
- 同 Agent / topic 的 10 分钟 cooldown、连续 Agent 3 轮、60 秒内第 3 条 human message、execution phase 均由 `route-decision.ts` 的确定性时钟逻辑执行；风险、结构化点名、球按合同保留，校准 +3 只穿透 human soft gate。
- `room_phase` 是持久 RouteJob 输入；当前尚无批准的 room-phase 权威 producer，生产创建值为 discussion，execution 值通过 server-private closed decision seam 验证，不从消息文本推断阶段。
- 自动化：`route-decision.test.ts` 明确覆盖 60 秒、10 分钟、2/3 轮的边界前后，以及 execution phase、风险、结构化点名、ball、±3 校准关系；topic 测试证明第 9 条不会影响固定窗口。

### 5. 创建时成员闭集、逐 Agent 最终 judgment、同步恢复

- `route_job_agents` 冻结创建时的 Agent 集合；`route.complete` 要求 judgment 集合与该集合精确相等，遗漏、重复、非成员或 routeAttempt 不一致均 409 fail closed。
- 每个 judgment 持久化 outcome、闭合 reasonCode、非空 reasonText、sourceMessageId、routeAttempt、decidedAt；当前权限变化改写为 `permission_denied`，provider omission/failure 与 mandatory 各有独立 reason。
- `room.route_judgment.recorded` 与 route lifecycle 进入原 room stream / outbox；`route-job`、`route-judgment` 进入 materialized/streaming repair，桌面显示独立 route judgment 卡且无 typing animation。
- 自动化：SQLite closed-set/CAS/成员移除测试、`core/sync.test.ts` closed repair/event 测试、desktop DOM 测试，以及真实进程 10,010-record 三副本 clear-cache/restart E2E。

### 6. 在线校准 +2/-2/+1/-1、幂等与截断

- human 的 useful/not_needed 与 👍/👎 分别写 immutable `route_calibration_facts`，按 `(agentId, topicKey)` 原子 upsert `route_calibration_scores` 并截断到 `[-4,4]`；factId 复放不会二次累计。
- authority 只允许 human 校准 Agent-authored message；human-human 直接拒绝。后续 RouteJob 创建时把同 topic 分数冻结到 `route_job_agents`。
- 自动化：`sqlite-authoritative-store.test.ts` 覆盖四种权重、重复事实、上下界截断、human-human 拒绝及后续同 topic Job 读到累计分；`route-decision.test.ts` 覆盖 `<=-3` 抑制与 `>=3` 穿透范围。

### 7. timeout/cancel/malformed、三次 attempt、非阻塞 ACK 与崩溃恢复

- RouteRuntime 每 room FIFO 串行、跨 room 最多 8 active、每 room 最多 32 queued；溢出的 durable Job 通过有界 recovery rescan 找回。
- 每次 Provider 调用最多 1 秒；transient / timeout / cancelled / malformed 最多 3 attempt，固定退避 250ms / 1s。第三次失败写全体 `provider_failed` judgment、`route.failed` 和 `attempts_exhausted` metric，mandatory intent 保留。
- `route.recover` 将 running attempt 权威改为 `runtime_restarted` failed 并创建新 attempt；所有 queued Job（包括未来 `nextRetryAt`）都会返回运行时，未来重试用不超过 1 秒的分段 timer 重装，避免重启后永久滞留。CAS 阻止旧 attempt 结果覆盖新 attempt。
- message ACK 只等待 message + RouteJob transaction，不等待 RouterProvider；composition root 在 ACK 后 notify。
- 自动化：runtime timeout/cancel/malformed、250/1000、queue overflow rescan、future retry timer；SQLite attempts/event/metric/CAS；真实 Worker/SQLite 与独立进程 restart E2E。

## 五、安全与恢复边界

- Router 与 AgentRuntime Provider 是两个独立 closed contract；Router 看不到完整会话、工具调用参数、HTTP headers、内部推理或凭据。
- OpenAI Router 仅从 server-side `SecretProvider` 取 secret；缺失时服务仍启动，路由按闭合 provider failure 重试/终结，不回退 fixture/mock。
- sentinel 自动化同时扫描数据库、WAL、请求正文、wire/route result、错误、stdout/stderr/diagnostic，secret 零命中。
- judgment/intent 与事件在 AuthorityWorker transaction 中提交；snapshot 构建期间的 route mutation 会使 snapshot_stale，客户端只对这个明确 409 做 250ms / 1s 有界重试。
- partial route/model 输入输出不进入 message/history；桌面只有权威 judgment 卡。Router 原始 response、headers 和 prompt 不持久化。
- T-0019 的球事实来源、T-0020 的 human preemption，以及 T-0017 的新 OpenItem 合同仍留在各自任务；本任务不伪造这些事实，也不提前实现其状态机。
