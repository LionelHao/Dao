# T-0039 真实身份、群与加入生命周期 · 交付说明

## 1. 做了什么

实现服务端权威的真人认证与可刷新/可撤销会话、受角色治理的群与两种加入生命周期、会话派生消息身份和彼此独立的真人邀请 / Agent 配置桌面入口。

审查入口：[GitHub PR #5](https://github.com/LionelHao/Dao/pull/5)；推送分支上的[本交付说明](https://github.com/LionelHao/Dao/blob/codex/t0039-identity-room-lifecycle/docs/deliveries/T-0039-%E7%9C%9F%E5%AE%9E%E8%BA%AB%E4%BB%BD%E7%BE%A4%E4%B8%8E%E5%8A%A0%E5%85%A5%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F-%E4%BA%A4%E4%BB%98%E8%AF%B4%E6%98%8E.md)可直接核对。

## 2. 逐条对照验收标准

1. **满足** — [`AuthenticationService`](../../packages/server/src/auth.ts) 通过 `IdentityAdapter` 验证账户，只为真人 actor 签发 opaque token；默认 access/refresh TTL 为 15 分钟/30 天，正常 refresh 只撤销被轮换的旧 token 对并在同一 family 追加新记录，显式 revoke 或复用已撤销 refresh 才撤销整个 family，持久化只含 token hash。[`auth.test.ts`](../../packages/server/src/auth.test.ts) 覆盖两个账户并发登录、进程重启恢复、新客户端 resume、过期边界、刷新重放和撤销；[`protocol.test.ts`](../../packages/server/src/protocol.test.ts) 与 [`websocket.test.ts`](../../packages/server/src/websocket.test.ts) 覆盖客户端提交 `authorId` / `authorKind` 返回 401 且不持久化、access 过期后的原连接刷新、全新连接仅凭 refresh token 恢复、跨账户刷新在持久化前 403 且不影响受害者 token、两客户端不同账户、服务重启和复用已撤销会话返回 403。`MessageDraft` 与严格帧解析都不允许客户端选择 actor。
2. **满足** — [`RoomLifecycleService`](../../packages/server/src/room-lifecycle.ts) 由真人创建群并自动设为 owner；`inviteHuman()` 生成只持久化 hash 的一次性邀请，`respondToHumanInvitation()` 只允许目标真人接受或拒绝。记录保存 `inviterActorId`、决定人、accepted/rejected 结果与时间；[`room-lifecycle.test.ts`](../../packages/server/src/room-lifecycle.test.ts) 覆盖接受、拒绝、重复消费和 JSON 重启恢复。
3. **满足** — [`RoomLifecycleService`](../../packages/server/src/room-lifecycle.ts) 在方法内部要求 owner/admin 才能重命名、归档、邀请、移除和配置 agent；[`room-lifecycle.test.ts`](../../packages/server/src/room-lifecycle.test.ts) 对普通 member 的五个直接调用逐一断言 `room_forbidden` / 403，并正向覆盖 owner 授予 admin 后的五项管理能力；权限不是通过隐藏桌面按钮代替。
4. **满足** — `HumanInvitationRequest` / `inviteHuman()` / `onInviteHuman` 与 `AgentConfigurationRequest` / `configureAgent()` / `onConfigureAgent` 是两套类型和接口。core request/membership guard 保证工具授权数组非空并维持人 / agent 类型分离；[`RoomLifecycleService.configureAgent()`](../../packages/server/src/room-lifecycle.ts) 进一步执行非空、无重复和 agent 声明能力子集校验；持久化 authority guard 要求非空、无重复，并在语义回放时核对目标 agent 的声明能力。空授权直调返回 400，空授权成员或审计快照被判损坏。桌面端也独立要求参与度和至少一项已声明工具授权，[`app.test.ts`](../../packages/desktop/src/renderer/app.test.ts) 会拒绝空权限和篡改值。[设计简报](../../.design/t0039-room-join/DESIGN_BRIEF.md)、[设计复审](../../.design/t0039-room-join/DESIGN_REVIEW.md) 与 [桌面截图](../../.design/t0039-room-join/screenshots/review-join-desktop-1280.png) 证明两条路径没有共用视觉；无可授予工具的 agent 仍在 actor 目录可见，但不能被编制进群。
5. **满足** — [`MessageService`](../../packages/server/src/service.ts) 的 `history` / `subscribe` / `send` 都读取当前成员目录；[`service.test.ts`](../../packages/server/src/service.test.ts) 对未加入 actor 的三条入口分别断言 403，[`websocket.test.ts`](../../packages/server/src/websocket.test.ts) 对三个未认证入口分别断言 401、对三个已认证非成员入口分别断言 403。会话还会在每次动作与实时投递前复验。
6. **满足** — [`RoomLifecycleService.removeMember()`](../../packages/server/src/room-lifecycle.ts) 只撤销当前成员关系，消息 JSONL 不被改写；[`service.test.ts`](../../packages/server/src/service.test.ts) 覆盖剩余成员仍可读取被移除者旧发言，以及被移除者的历史、订阅、发送和寻址立即失效；[`websocket.test.ts`](../../packages/server/src/websocket.test.ts) 覆盖已建立实时订阅停止。`room.member.removed` 审计包含执行者、目标、结果和时间，并由 [`room-lifecycle.test.ts`](../../packages/server/src/room-lifecycle.test.ts) 验证可通过 `audit(roomId)` 查询。

## 3. 参照与偏离

- **参照什么** — 具体参照 Buzz 的 `buzz-core` 领域类型边界、`buzz-auth::AuthContext` 身份上下文、`buzz-relay::handlers::event/ingest` 的身份匹配与持久接受管线，以及 `buzz-relay::handlers::req` + `SubscriptionRegistry` 在历史/实时读取前做访问过滤和先注册订阅的顺序。
- **怎么翻译** — `IdentityAdapter` / `AuthenticationService` 对应认证上下文，`RoomLifecycleService` 对应成员与授权目录，零 I/O 的 `@native-im/core` 对应稳定领域类型；`MessageService` 与 WebSocket composition adapter 把服务端 principal、持久化 append、历史查询和实时订阅串起来。状态先用可注入 store 持久化，为下一阶段替换存储保留接口。
- **为何偏离** — 不采用 Buzz 的 Nostr 公钥、多租户 community、Redis、媒体和工作流引擎；本产品使用本地账户 + opaque rotating token，并按 PRD 2.3 #6/#13 把真人“等待接受/拒绝”的社会邀请与 agent“参与度 + 工具授权立即生效”的能力配置彻底分开。当前 JSON/JSONL 是 T-0039 的重启恢复落脚点，不假装已经具备 Buzz 生产存储的完整事务能力。

## 4. 解锁了什么

本次交付满足 T-0040「服务端权威持久化、版本迁移、可重放分发、事件游标与 ACK」的身份、成员权限和消息入口前置契约；待 @lionel 将 T-0039 验证为 `verified` 后，T-0040 才应按 Blueprint 依赖正式进入可认领状态。

T-0040 的 Blueprint 已定边界完整抄录在[协议文档](../protocols/identity-room-lifecycle.md)：九类状态持久化与重启读回、稳定 ID / 幂等重试、三客户端游标恢复、提交后分发前故障注入、事务 outbox 或等价耐久机制、版本迁移，以及清空客户端缓存后的权限内完整恢复。T-0040 不能重新开放客户端指定 actor，也不能合并两种加入语义；具体存储技术仍由 T-0040 决策。

### 已知边界与自检说明

- 当前 session 和 room lifecycle 使用各自的 version 1 JSON 原子替换，消息使用 JSONL；T-0040 已明确要求覆盖全部九类状态的权威持久化、正式迁移、事务 outbox 或等价机制和事件游标，但没有预先规定跨进程 writer lease 或所有跨状态事务的粒度。
- 当前 history 没有分页；超出 WebSocket outbound 上限的单帧会在发送前终止连接，但帧仍需先序列化才能计算 UTF-8 字节。稳定 cursor 和游标过期后的全量修复属于 T-0040 已定范围；分页、单页字节上限和大历史内存上限是下方的 `criteria-tighten` 建议。
- legacy JSONL 行沿用基线的宽松 `isMessage` guard；T-0040 的 schema migration 应把历史消息读取也收紧为 closed schema，并给损坏行提供可诊断的恢复路径。
- 在全新 worktree 中直接单跑 `pnpm test`，若 `packages/core/dist` 尚未生成，依赖编译产物的包可能先失败；规定顺序先执行 `pnpm typecheck` 会生成 workspace 构建产物，随后 test 正常运行。这是当前脚本的基线顺序约束，最终交付仍必须逐条执行规定五命令且全部退出 0。
- WebSocket 在关闭或终止时会同步阻止排队中的后续帧；已经开始并进入底层存储的单个操作可能在连接关闭后完成，但不再向关闭连接响应。跨进程 writer lease 和进行中操作的统一取消语义是后续 hardening 建议，不列作 T-0040 已有验收标准。

### criteria-tighten 建议（未修改 T-0039 标准）

1. 为审计历史增加规模上限或要求状态校验使用迭代式最大时间计算，避免将来超大 audit 数组经 `Math.max(...timestamps)` 触发参数数量上限。
2. 把“重启恢复”进一步写明为单进程持久化恢复；T-0040 已要求 schema migration，建议另行收紧跨进程 writer lease 与跨状态事务粒度，防止以后把 JSON 原子替换误读为完整事务存储。
3. 后续成员治理标准应明确 owner 转移、多 owner 或最后 owner 退出的产品语义；T-0039 当前只允许 owner 调整 admin/member，且禁止移出 owner。
4. 为历史查询增加分页与单页序列化字节上限，并要求 T-0040 把 legacy JSONL 迁入其选定的版本化权威存储时验证 closed message schema，避免把连接终止误当作大历史的完整容量方案；稳定 cursor 已是 T-0040 现有标准，不在此重复建议。
5. 请 @lionel 把标准 1 的“篡改 actor ID”收紧为可直接执行的帧场景，例如“`message.send.message` 出现 `authorId` 或 `authorKind` 时返回 401 且不持久化”；本轮已按该解释实现，但明确字段能避免以后把 token 篡改与作者字段注入混为一谈。
