# T-0039 真实身份、群与加入生命周期 · 交付说明

## 1. 做了什么

实现服务端权威的真人认证与可刷新/可撤销会话、受角色治理的群与两种加入生命周期、会话派生消息身份和彼此独立的真人邀请 / Agent 配置桌面入口；当前已知一项交付前缺口是服务端尚未拒绝零工具 grant 的 Agent 配置。

## 2. 逐条对照验收标准

1. **满足** — [`AuthenticationService`](../../packages/server/src/auth.ts) 通过 `IdentityAdapter` 验证账户，只为真人 actor 签发 opaque token；默认 access/refresh TTL 为 15 分钟/30 天，refresh 旋转和 revoke 都撤销 token family，持久化只含 token hash。[`auth.test.ts`](../../packages/server/src/auth.test.ts) 覆盖两个账户并发登录、进程重启恢复、新客户端 resume、过期边界、刷新重放和撤销；[`websocket.test.ts`](../../packages/server/src/websocket.test.ts) 覆盖两客户端不同账户、服务重启、篡改 `authorId` / `authorKind` 为 403、已撤销会话为 403、无效/篡改 token 为 401。`MessageDraft` 与严格帧解析都不允许客户端选择 actor。
2. **满足** — [`RoomLifecycleService`](../../packages/server/src/room-lifecycle.ts) 由真人创建群并自动设为 owner；`inviteHuman()` 生成只持久化 hash 的一次性邀请，`respondToHumanInvitation()` 只允许目标真人接受或拒绝。记录保存 `inviterActorId`、决定人、accepted/rejected 结果与时间；[`room-lifecycle.test.ts`](../../packages/server/src/room-lifecycle.test.ts) 覆盖接受、拒绝、重复消费和 JSON 重启恢复。
3. **满足** — owner/admin 才能在服务端方法内部重命名、归档、邀请、移除和配置 agent；普通 member 的五个直接调用逐一断言 `room_forbidden` / 403。owner 可授予/收回 admin，admin 的五项管理能力也有正向自动化覆盖；权限不是通过隐藏桌面按钮代替。
4. **未满足（待根代理修复）** — `HumanInvitationRequest` / `inviteHuman()` / `onInviteHuman` 与 `AgentConfigurationRequest` / `configureAgent()` / `onConfigureAgent` 已是两套类型和接口；桌面端要求参与度和至少一项已声明工具授权，[`app.test.ts`](../../packages/desktop/src/renderer/app.test.ts) 也会拒绝空权限和篡改值。[设计简报](../../.design/t0039-room-join/DESIGN_BRIEF.md)、[设计复审](../../.design/t0039-room-join/DESIGN_REVIEW.md) 与 [桌面截图](../../.design/t0039-room-join/screenshots/review-join-desktop-1280.png) 证明两条路径没有共用视觉。但 [`RoomLifecycleService.configureAgent()`](../../packages/server/src/room-lifecycle.ts) 当前只验证 `toolPermissions` 无重复且为声明能力子集，仍接受空数组；验收总则要求接口层也独立落实，因此必须在交付前增加服务端非空校验与自动化测试，完成后才能将本条改为“满足”。
5. **满足** — [`MessageService`](../../packages/server/src/service.ts) 的 `history` / `subscribe` / `send` 都读取当前成员目录；[`service.test.ts`](../../packages/server/src/service.test.ts) 对未加入 actor 的三条入口分别断言 403，[`websocket.test.ts`](../../packages/server/src/websocket.test.ts) 对三个未认证入口分别断言 401、对三个已认证非成员入口分别断言 403。会话还会在每次动作与实时投递前复验。
6. **满足** — 移除只撤销当前成员关系，消息 JSONL 不被改写；剩余成员仍能读取被移除者的旧发言，被移除者的历史、订阅、发送、寻址和已建立实时投递立即失效。`room.member.removed` 审计包含执行者、目标、结果和时间，并能通过 `audit(roomId)` 查询；服务测试同时覆盖历史保留与活跃订阅停止。

## 3. 参照与偏离

- **参照什么** — Buzz 把身份/认证、成员目录、授权过滤、持久化 ingest 与 WebSocket transport 拆成独立模块，并在历史查询与事件投递之前执行成员校验。
- **怎么翻译** — `IdentityAdapter`、`AuthenticationService`、`RoomLifecycleService`、`MessageService` 和 WebSocket composition adapter 形成 TypeScript 边界；连接只持有服务端签发 principal，消息和房间访问每次查询当前成员目录。状态先用可注入 store 持久化，为下一阶段替换存储保留接口。
- **为何偏离** — 不采用 Buzz 的 Nostr 公钥、多租户 community、Redis、媒体和工作流引擎；本产品使用本地账户 + opaque rotating token，并按 PRD 2.3 #6/#13 把真人“等待接受/拒绝”的社会邀请与 agent“参与度 + 工具授权立即生效”的能力配置彻底分开。当前 JSON/JSONL 是 T-0039 的重启恢复落脚点，不假装已经具备 Buzz 生产存储的完整事务能力。

## 4. 解锁了什么

本次交付满足 T-0040「统一 SQLite / 迁移 / outbox / 事件游标与 ACK」的身份、成员权限和消息入口前置契约；待 @lionel 将 T-0039 验证为 `verified` 后，T-0040 才应按 Blueprint 依赖正式进入可认领状态。

T-0040 的交接边界已固化在[协议文档](../protocols/identity-room-lifecycle.md)：统一 session/room/audit/message 事务持久化、schema migration、事务 outbox、稳定游标与重放、崩溃/失败/并发 writer 故障注入；不能重新开放客户端指定 actor，也不能合并两种加入语义。

### 已知边界与自检说明

- 当前 session 和 room lifecycle 使用各自的 version 1 JSON 原子替换，消息使用 JSONL；跨文件事务、正式迁移、跨进程 writer、outbox 和事件游标属于 T-0040，不把它们误报为已完成。
- 在全新 worktree 中直接单跑 `pnpm test`，若 `packages/core/dist` 尚未生成，依赖编译产物的包可能先失败；规定顺序先执行 `pnpm typecheck` 会生成 workspace 构建产物，随后 test 正常运行。这是当前脚本的基线顺序约束，最终交付仍必须逐条执行规定五命令且全部退出 0。
- WebSocket 在关闭或终止时会同步阻止排队中的后续帧；已经开始并进入底层存储的单个操作可能在连接关闭后完成，但不再向关闭连接响应。跨进程写入和统一取消语义留给 T-0040。

### criteria-tighten 建议（未修改 T-0039 标准）

1. 为审计历史增加规模上限或要求状态校验使用迭代式最大时间计算，避免将来超大 audit 数组经 `Math.max(...timestamps)` 触发参数数量上限。

3. 后续成员治理标准应明确 owner 转移、多 owner 或最后 owner 退出的产品语义；T-0039 当前只允许 owner 调整 admin/member，且禁止移出 owner。
