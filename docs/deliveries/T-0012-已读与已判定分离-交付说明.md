# T-0012 已读 / 已判定分离 · 交付说明

## 1. 做了什么

新增相互独立的人类已读回执与 agent 发言判定记录，并将判定原因、三态及不发言时的可见记录显示在消息预览中。

**视觉复检修订：** `.agent-judgement` 现追加到 agent 消息的 `.message-content` 内容列，而非 `.message--agent` 的 CSS grid 根；长原因可在 734px 内容列内正常换行，不会成为窄的隐式 grid item。

## 2. 逐条对照验收标准

1. **满足** — 「人显示已读回执（谁读了）；agent 不显示已读，改显示【已判定】三态之一：将回应 / 无需回应 / 被抑制」：`HumanReadReceipt` 与 `AgentJudgement` 分开；预览显示“✓✓ 已读：周安全、陈研发”及三条不同 `.agent-judgement`，后者都位于 agent `.message-content` 内容列。
2. **满足** — 「每条「已判定」必须携带一句可读原因（如「未命中我的领域」「同话题冷却期内，还剩 N 分钟」），原因来自发言判定逻辑而非固定文案」：`evaluateAgentJudgement` 根据 `matchesDomain` / `cooldownRemainingMinutes` 生成原因；服务端测试确认不同输入给出“未命中我的领域”和“还剩 7 分钟”。
3. **满足** — 「存在测试：agent 收到一条消息但不发言时，界面上必然出现一条「已判定」记录——不允许静默沉默」：服务端 `matchesDomain: false` 仍写入 `no_response_needed`；桌面测试断言三个 agent judgement 均渲染、没有 `.message--agent > .agent-judgement`，并验证长冷却原因的父节点为 `.message-content`。
4. **满足** — 「已读与已判定在数据模型上是两个不同的结构，不共用同一张表或同一字段」：分别使用 `humanReadReceipts: HumanReadReceipt[]` 与 `agentJudgements: AgentJudgement[]`，查询 API 亦分开。

## 3. Buzz 参照与偏离

- **参照了什么：** Buzz `StoredEvent` 的可重放记录观念，以及其队列对 agent 异步命运的显式分类。
- **怎么翻译：** 本项目以两个 TypeScript 记录集合保留人读过与 agent 判定过的事实，理由作为路由输入的可读派生结果。
- **为何偏离：** 不复制 Nostr kind/tag 或 Buzz 通用队列；Buzz 仍将 agent 放在人的已读抽象中，本产品按 PRD 2.3 #2 使沉默可解释。

## 4. 解锁了什么

提供发言判定的唯一外部可观测面，供 **T-0016 四层发言判定 · 单次路由架构** 在 M3 扩展路由模型。
