## 二、六条验收标准与代码、测试证据

### 1. 闭合权威事实、唯一 owner 与四态不变量

- `packages/core/src/collaboration.ts` 定义 `OpenItem`、`OpenItemStatus`、三种闭合 origin 与严格 guard；`awaiting` / `transferred` 必须有唯一 `currentOwnerId`，`transferred` owner 必须等于链尾，`answered` / `deferred` 必须清空 owner 并具有 `respondedAt`，未知键、未知状态、断裂链和 terminal 非空 owner 均拒绝。
- `packages/server/src/persistence/schema.ts` 的 immutable v8 重建 `open_items`，以 STRICT table、CHECK 与 insert/update trigger 在数据库语句边界复核同 room source、当前成员、状态/owner/origin、Agent proposal provenance；terminal 行不可复活，转交链只能追加且旧节点不可改写。
- 自动化：`packages/core/src/collaboration.test.ts` 覆盖类型/guard 正反例；`packages/server/src/persistence/schema.test.ts` 覆盖数据库约束、转交链改写和 terminal reopen 拒绝。

### 2. 三种产生方式、幂等与闭合 Agent proposal

- human `open-item.create` 只接受 `human_mention` / `manual_unfinished`、同 room source message 与当前 room member target；human mention 的 target 必须是 human。AuthorityWorker 在一个 transaction 内写 fact、room event、outbox 与 idempotency acknowledgement。
- T-0041 OpenAI Responses Adapter 仅在 authority 提供当前 room targets 时声明保留的严格函数 `dao_propose_open_item`；参数闭合为 risk/challenge、当前 `targetActorId`、当前 `sourceMessageId`、非空 reason/content。AgentRuntime 精确解析后通过 server-private `open-item.propose` seam 复核 execution、Agent 身份、source、room 与 target，不从自然语言猜 proposal 或 target，也不向 WebSocket 暴露 Agent proposal 命令。
- 自动化：`sqlite-authoritative-store.test.ts` 覆盖三种来源、重复 key 同 fact、payload 冲突 409、跨 room/伪造 execution 拒绝；`openai-responses-provider.test.ts` 与 `agent-runtime-service.test.ts` 覆盖 strict function schema、无 target 不声明、closed proposal continuation 与 malformed 零提交。

### 3. @human 请求与 @agent 调用不双写、不串义

- human mention OpenItem 与 AgentExecution 保持独立命令、fact table 和事件类型；`human_mention` 指向 Agent 在 authority 层闭合拒绝，Agent invocation 继续只走 T-0041 execution 管线。
- `sqlite-authoritative-store.test.ts` 在同一真实 worker/SQLite 用例中分阶段断言：human mention 后 `open_items=1`、`agent_executions=0` 且只有 `room.open_item.changed`；Agent invocation 后 OpenItem 数不变、execution/event 各新增一次。
- `packages/server/src/primitives.test.ts` 的 T-0013 addressing 用例继续锁定 human request 可转交、Agent invocation 可 interrupt 且 Agent 不能拒绝 invocation，防止 OpenItem 与 AgentExecution 类型或行为合并。

### 4. human/agent 转换权限、失败事实与持球边界

- AuthorityWorker 的权限矩阵允许 human owner answer/defer/cannot-answer/transfer；human requester 非 owner 只可显式 transfer/defer；Agent owner 只能 answer，不能 defer、cannot-answer 或 transfer。target 必须仍是当前 room member；非 owner 403，terminal/stale CAS 409。
- transfer 原子追加 `{fromId,toId,reason,transferredAt}`，应用层 CAS 与 v8 trigger 同时禁止覆盖历史链。
- Agent 最终 failed/dead-letter transaction 会自动为其仍持有且关联 source execution/message 的 active OpenItem 追加 `open_item_agent_failures` 与 `room.open_item.agent_attempt_failed`；OpenItem 保持 active、owner 不变。T-0041 人工 retry 创建新 execution/attempt，不复活或改写失败事实。
- 自动化：SQLite 权限测试覆盖 Agent 拒绝/搁置/转交、requester 代 owner cannot-answer、human 转交、terminal 重放与成员移除；real AuthorityWorker runtime 测试覆盖最终失败事实与 owner 保持。

### 5. 同事务、重启、清缓存、多客户端与成员移除

- OpenItem create/transition/proposal/failure 均复用 AuthorityWorker transaction、room stream、outbox 与 idempotency；`packages/core/src/sync.ts`、`snapshot-worker.ts` 将 `open-item` 与 `open-item-agent-failure` 纳入 materialized/streaming repair 稳定顺序。
- `packages/server/src/authority.e2e.test.ts` 通过真实子进程、WebSocket 与 SQLite 创建并重放 human OpenItem、执行 terminal transition、验证 409、清 snapshot cache repair、重启，再断言唯一 fact 与两条状态事件。
- SQLite 测试证明成员移除不会删除历史 source message 或 OpenItem，但后续动作按当前 membership 返回 403；snapshot、sync 与 replica 测试继续覆盖多客户端 live/retained/expired/clear-cache 路径。

### 6. 桌面 D-01 四态与 human-only actions

- `packages/desktop/src/renderer/app.ts` / `styles.css` 显示 OpenItem 内容、唯一 owner、source/origin/source message 与 awaiting/answered/deferred/transferred 四态；active human request 提供回应、搁置、转交，terminal 不再显示动作。
- AgentExecution 保持独立卡片，只显示其运行状态与 interrupt，不出现 OpenItem 的 human-only 请求动作；未增加 Agent typing animation，也未把 partial preview 写入权威历史。
- `packages/desktop/src/renderer/app.test.ts` 的 30 项 DOM 测试覆盖四态、owner/source/origin、active/terminal action 差异，以及 Agent invocation 与 human request 的 class/操作隔离；WebSocket/protocol 负例覆盖 closed frame、403/404/409。

## 五、安全、权限与恢复边界

- Agent proposal 只能由 runtime 识别 OpenAI strict reserved function 后，以 server-minted internal Agent context 进入 AuthorityWorker；普通 WebSocket 只有 human create/transition frame，不能伪造 Agent requester、execution 或 failure。
- Provider 可见的 proposal target 是 authority 当次返回的当前 room member 闭集；提交时再次复核 membership、room、source 与 execution provenance，消除模型输出直接写库的路径。
- OpenItem event/repair 只保存闭合事实与失败 reason code；不保存 Provider 原始正文、HTTP headers、内部推理、secret 或 partial stream。T-0041 的 secret sentinel、取消、重试、恢复与 side-effect 边界保持不变。
- Agent execution failed 不是 OpenItem 回滚或自动转交；失败是 append-only 事实，owner 保持，只有有权 human 的显式 transition 才改变承诺归属。BallInCourt 的聚合/优先级等待 T-0019，本任务只保持其所需的 active-owner 权威事实。
- free-text mention/proposal 不在 server 端猜测：上游 addressing/UI 必须显式提供闭合 source/target/creation kind，Agent 必须使用 reserved structured function。
